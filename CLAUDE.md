## Project Overview

**TorchGWAS** is a modular Python library for GPU-accelerated Genome-Wide Association Studies (GWAS) using PyTorch. It replicates and extends functionality from established tools like GEMMA and GAPIT, targeting 4th-decimal-place agreement with their p-values. Supports both diploid and polyploid organisms.

**Status**: Active development. Phases 0-47 complete (2102 tests pass, 44 skipped). Version 0.1.0 (Alpha). V1 core (Phases 0-13) fully implemented with GEMMA/GAPIT reference equivalence. Post-V1 novel models (Phases 14-19) implemented: multi-kernel LMM, GxE-LMM, set-based tests, Bayesian variable selection (SuSiE + CAVI), GPU-accelerated imputation, and multi-environment GWAS (MET: reaction-norm + FA(k) + multi-kernel). Phase 23: Within-family / family-aware GWAS with dual-scan attenuation diagnostics for confounding detection. Phase 24: LD-conditional GWAS with GCTA-COJO-style stepwise conditioning and conditional persistence metrics. ## Planned Architecture

The data flow follows: **format detection → imputation/phasing → QC/preprocessing → genotype encoding → GRM → eigendecomposition → null fitting → scan loop → multiple testing → reporting**.

### Core Modules

- **`torchgwas.io`** — Auto-detect and read all major formats (PLINK BED/PGEN, VCF/BCF, BGEN, HapMap, Zarr, CSV dosage). Format validation and conversion utilities.
- **`torchgwas.preprocess`** — Imputation (built-in mean/KNN/LD-based + GPU Li-and-Stephens HMM + deep learning autoencoder + external BEAGLE/IMPUTE5/Minimac4 wrappers), phasing, QC (MAF/HWE/call rate), standardization (ploidy-aware), polyploid gene-action model encoding.
- **`torchgwas.linalg`** — Kinship/GRM computation (diploid + polyploid, LOCO), EED, batched Cholesky.
- **`torchgwas.models`** — `BaseModel` protocol with `fit_null()` and `score_chunk()`:
  - `GLM`, `SingleTraitLMM`, `MultiTraitLMM`, `FarmCPU`, `BLINK`
  - Novel (post-V1, implemented): `MultiKernelLMM`, `GxELMM`/`HetLMM`, `SetBasedScanner`, `BayesianVS` (SuSiE + CAVI)
  - Novel (implemented): `ThresholdLinearModel` — Bermann et al. 2026 threshold-linear for ordinal+continuous traits
  - Novel (implemented): `WithinFamilyLMM` — Within-family GWAS with dual-scan attenuation diagnostics (Young et al. 2022)
  - Novel (implemented): `ConditionalLMM` — LD-conditional GWAS with COJO-style stepwise conditioning and persistence metrics
  - Novel (implemented): `MultiTraitMultiEnvLMM` — MT-MET GWAS with separable Kronecker, unstructured, or FA(k) genetic covariance
  - Novel (implemented): `OCFLMM` — Orthogonal Cross-Fit LMM with DML-valid debiased inference, HC sandwich variance
  - Novel (implemented): `KnockoffLMM` — Group knockoff FDR-controlled GWAS under LMM (Sesia et al. 2020)
  - Novel (implemented): `GULM` — Genotype-Uncertainty LMM with dosage-variance–corrected score test
  - Novel (implemented): `LROLMM` — Leave-Region-Out LMM with block-level LOCO proximal decontamination
  - Novel (implemented): `BinaryGLM`, `OrdinalGLM`, `MultinomialGLM` — GLM family (logistic, proportional odds, multinomial logit) with score tests and SPA
  - Novel (implemented): `BinaryGLMM`, `OrdinalGLMM`, `MultinomialGLMM` — GLMM family with PQL null fitting (SAIGE-style)
  - Novel (implemented): `SurvivalGLMM` — Cox PH frailty model with Breslow-Clayton PQL and martingale residual score test (SPACox/GATE/COXMEG)
  - Novel (implemented): `RandomRegressionLMM`, `SpatioTemporalRR` — longitudinal + spatio-temporal GWAS via Legendre / B-spline / 2D P-spline bases (Phase 38)
  - Novel (implemented): `HaplotypeGWAS` — Haplotype-based GWAS with HTR, block, window, and SKAT methods (Phase 46)
  - Novel (implemented): `HaplotypeMultiEnvGWAS`, `HaplotypeMultiTraitGWAS`, `HaplotypeMTMETGWAS` — Multi-env/multi-trait/MT-MET haplotype GWAS via thin composition (Phase 47)
  - Novel (implemented): `RandomRegressionMultiEnvLMM` — multi-environment longitudinal GWAS via separable Kronecker `K_coef ⊗ Vg_env` (Phase 39); 9 RR-aware contrast tests; pooled-time invariant; thin composition over `MultiTraitMultiEnvLMM`
- **`torchgwas.scan`** — `UnifiedScanner` streams chunks through any model via adapters.
- **`torchgwas.stats`** — Multiple testing: Bonferroni, Holm, BH, BY, Storey q-value, simpleM/M_eff, GPU-accelerated permutation, weighted FDR, Cauchy combination, local FDR, IHW (covariate-adaptive weighting), AdaPT (covariate-adaptive thresholding).
- **`torchgwas.ld`** — LD block detection: 13 methods (4 classical, 5 novel, 3 literature, 1 diagnostic). Pairwise LD (r², D', CI), graph utilities (Laplacian, spectral partition, MWIS), change-point detection (PELT), uncertainty-corrected LD, PLINK .blocks.det compatibility, cross-method comparison metrics. Validated against PLINK 1.9 --blocks. Works for diploid and arbitrary polyploid.
- **`torchgwas.optim`** — 6-mode optimizer stack with automatic fallback: PX-EM → AI-REML → LBFGS-autograd → MM algorithm → PCG iterative → derivative-free rescue.

## Key Design Decisions

- **Hardware-agnostic tensors**: All operations use `torch.Tensor` with `.to(device)` for CPU/GPU portability.
- **Polyploid-first**: Genotypes stored as float tensors in [0, k] for arbitrary ploidy k. Gene-action models (additive, 1-dom through k-1-dom, diplo-additive, overdominant) tested per SNP.
- **Format intelligence**: Auto-detect, validate, and convert between all major genotype formats. Pre-flight checks before any GWAS run. Deterministic sample alignment with three-way ID intersection and alignment manifest output.
- **Variant QC Parquet output**: Per-variant MAF, heterozygosity, missingness, HWE p-value, and filter status written to Parquet before scan — enables QA against GEMMA/GAPIT defaults for both diploid and polyploid.
- **Integrated imputation**: Built-in simple imputation + pluggable external tools (BEAGLE, IMPUTE5, Minimac4, STITCH) with quality tracking.
- **Layered optimizer stack**: Adapted from ASReml-class charter + PyTorch autograd extensions.
- **Precision management**: AMP for FP16/BF16 in I/O and GRM; FP64 mandatory for statistical inference.

**V1 scope**: V1 statistical deliverable focuses on Gaussian quantitative-trait GWAS for reference-tool equivalence. Validation gates use numerical tolerance (not bitwise identity) to account for GPU non-determinism.
